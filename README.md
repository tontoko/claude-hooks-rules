# Claude Code Hooks Rules

Claude Codeの動作を改善するためのHookスクリプト集です。TDD（テスト駆動開発）の徹底、曖昧な指示の明確化、コンテキストの保持などを自動化します。

さらに、特定のキーワードで有効化できる特殊モードも提供しています。

## 機能

### 1. ワークフロールールの自動適用
- **TDD厳守**: 実装前に必ずテストを先に書くよう促す
- **実装前の確認**: ユーザーの意図が曖昧な場合、Claudeが判断して要件を明確化
- **設計の確認**: 実装前に影響範囲や代替案を検討

### 2. コンテキストの保持
- 直近3件のユーザー指示を常に記録
- Compact Summary実行後も作業内容を忘れない
- 長時間の作業でも継続性を維持

### 3. コードレビューの促進
- 機能完成時に俯瞰的な視点でのレビューを促す
- 冗長なコードや改善可能な設計を指摘

### 4. カスタムサブエージェントシステム

#### 概要
Claude Codeをメインオーケストレーターとして拡張し、9つの専門サブエージェントが並列で協調動作するシステムです。各エージェントは特定の領域に特化し、独立して動作しながらメインに報告を行います。

#### メインオーケストレーターの動作
1. **タスク受信**: ユーザーからのリクエストを受け取る
2. **タスク分類**: タスクの性質を判断（新規開発・改修 or その他）
3. **エージェント選択**: 
   - 新規開発・改修: 全エージェントを段階的に起動
   - その他のタスク: 必要なエージェントのみ選択的に起動
4. **並列実行管理**: 複数のエージェントを同時に実行
5. **結果統合**: 各エージェントからの報告を統合
6. **最終レスポンス**: ユーザーに総合的な結果を返す

#### 各サブエージェントの役割と責務

##### 1. 要件分析エージェント (requirements_agent.py)
- **責務**: ユーザー要件の分析と明確化
- **機能**:
  - 曖昧な要件の洗い出し
  - 機能要件・非機能要件の整理
  - 制約事項の確認
  - ユースケースの定義

##### 2. 設計エージェント (design_agent.py)
- **責務**: システム設計とアーキテクチャ決定
- **機能**:
  - アーキテクチャパターンの提案
  - モジュール構成の設計
  - データモデル設計
  - インターフェース定義

##### 3. 実装エージェント (implementation_agent.py)
- **責務**: コード実装とベストプラクティスの適用
- **機能**:
  - クリーンコードの実装
  - デザインパターンの適用
  - エラーハンドリング実装
  - コーディング規約の遵守

##### 4. レビューエージェント (review_agent.py)
- **責務**: コード品質の評価と改善提案
- **機能**:
  - コードレビュー実施
  - リファクタリング提案
  - 可読性・保守性の評価
  - ベストプラクティス準拠チェック

##### 5. テストエージェント (test_agent.py)
- **責務**: テスト戦略とテストコード作成
- **機能**:
  - テストケース設計
  - 単体テスト作成
  - 統合テスト作成
  - テストカバレッジ分析

##### 6. デプロイエージェント (deploy_agent.py)
- **責務**: デプロイメント戦略と環境構築
- **機能**:
  - CI/CDパイプライン設計
  - 環境別設定管理
  - デプロイスクリプト作成
  - ロールバック戦略立案

##### 7. ドキュメントエージェント (docs_agent.py)
- **責務**: ドキュメント作成と保守
- **機能**:
  - API仕様書作成
  - アーキテクチャドキュメント作成
  - ユーザーマニュアル作成
  - 開発者向けガイド作成

##### 8. パフォーマンスエージェント (performance_agent.py)
- **責務**: パフォーマンス最適化と監視
- **機能**:
  - ボトルネック分析
  - 最適化提案
  - キャッシュ戦略立案
  - 負荷テスト設計

##### 9. セキュリティエージェント (security_agent.py)
- **責務**: セキュリティ評価と対策
- **機能**:
  - 脆弱性スキャン
  - セキュリティベストプラクティス適用
  - 認証・認可の実装提案
  - データ保護戦略立案

#### 開発フローの説明

##### 新規開発・改修の場合
1. **要件分析フェーズ**: 要件分析エージェントが起動し、要件を明確化
2. **設計フェーズ**: 設計エージェントがアーキテクチャを提案
3. **実装フェーズ**: 実装・テスト・セキュリティエージェントが並列で動作
4. **レビューフェーズ**: レビューエージェントがコード品質を評価
5. **ドキュメント化**: ドキュメントエージェントが必要な文書を作成
6. **デプロイ準備**: デプロイエージェントが環境構築を支援

##### その他のタスクの場合
- バグ修正: テスト・実装・レビューエージェントのみ
- パフォーマンス改善: パフォーマンス・実装・テストエージェント
- セキュリティ対応: セキュリティ・実装・テストエージェント
- ドキュメント更新: ドキュメントエージェントのみ

#### 並列実行の仕組み

1. **非同期実行**: 各エージェントは独立したプロセスとして動作
2. **メッセージキュー**: エージェント間の通信はキューを介して実施
3. **結果集約**: メインオーケストレーターが各エージェントの結果を収集
4. **競合解決**: 同じリソースへのアクセスは自動的に調整
5. **エラーハンドリング**: 個別エージェントの障害は全体に影響しない

#### 設定方法と使用方法

##### 初期設定
1. エージェントスクリプトに実行権限を付与:
   ```bash
   chmod +x agents/*.py
   ```

2. `~/.claude/settings.json`にエージェントフックを追加:
   ```json
   {
     "user_hooks": {
       "on_request": [
         "/path/to/claude-hooks-rules/agents/requirements_agent.py",
         "/path/to/claude-hooks-rules/agents/design_agent.py",
         "/path/to/claude-hooks-rules/agents/implementation_agent.py",
         "/path/to/claude-hooks-rules/agents/review_agent.py",
         "/path/to/claude-hooks-rules/agents/test_agent.py",
         "/path/to/claude-hooks-rules/agents/deploy_agent.py",
         "/path/to/claude-hooks-rules/agents/docs_agent.py",
         "/path/to/claude-hooks-rules/agents/performance_agent.py",
         "/path/to/claude-hooks-rules/agents/security_agent.py"
       ]
     }
   }
   ```

##### 使用例

###### 新機能の開発
```
ユーザー認証機能を実装してください
```
→ 全エージェントが協調して要件分析から実装、デプロイまでをサポート

###### バグ修正
```
ログイン時のエラーを修正してください
```
→ 必要なエージェントのみが選択的に起動

###### カスタムエージェント指定
```
@security @performance ログイン処理を最適化してください
```
→ 指定されたエージェントを優先的に起動

### 5. モード管理システム

統一的なモード管理システムで、複数のモードを同時に有効化できます。

#### モードの操作

```
# モードを有効化（既存のモードを置き換え）
mode: explain
mode: explain debug test

# モードを追加（既存のモードに追加）
mode on: explain
mode on: debug test

# モードを無効化（特定のモードのみ）
mode off: explain
mode off: debug test

# すべてのモードを無効化
mode: off
mode clear
mode reset

# 現在のモードを確認
mode list
mode status
```

#### 利用可能なモード

##### 解説モード (explain/explanation)
- コード編集時に初心者向けの解説ドキュメントを自動生成
- `docs/code-explanation/`ディレクトリに保存
- なぜその実装方法を選んだか、設計の意図を記録

## インストール

### 1. リポジトリのクローン
```bash
git clone https://github.com/your-username/claude-hooks-rules.git
cd claude-hooks-rules
```

### 2. スクリプトに実行権限を付与
```bash
chmod +x hooks/*.py
chmod +x agents/*.py
```

### 3. Claude Code設定ファイルの更新

`example.settings.json`の内容を参考に、`~/.claude/settings.json`を編集します：

```bash
# 設定ファイルを開く
open ~/.claude/settings.json

# または、提供されている設定をコピー（パスを自分の環境に合わせて修正）
cp example.settings.json ~/.claude/settings.json
```

**重要**: `example.settings.json`内のパスを自分の環境に合わせて修正してください：
- `/Users/user-name/` → `/Users/あなたのユーザー名/`

### 4. Claude Codeを再起動

設定を反映させるために、Claude Codeを再起動してください。

## 使い方

通常通りClaude Codeを使用するだけで、以下が自動的に適用されます：

### テスト例

1. **実装前の確認テスト**
   ```
   認証機能を追加できればいいかなと思った
   ```
   → Claudeが意図を確認し、要件を明確化します

2. **TDDルールのテスト**
   ```
   ユーザー登録APIを実装して
   ```
   → テストを先に書いてから実装します

3. **Compact後のコンテキスト保持テスト**
   ```
   1. 何か指示を出す
   2. /compact を実行
   3. 「続きをやって」と指示
   ```
   → compact前の指示を覚えています

## カスタマイズ

### ワークフロールールの変更

`hooks/workflow_instructions.py`の`get_workflow_rules()`関数を編集して、独自のルールを追加できます。

### 保存する指示の件数変更

デフォルトでは直近3件の指示を保存しますが、以下のファイルで変更可能です：
- `workflow_instructions.py`: `save_current_prompt()`関数内の`[:3]`
- `preserve_context.py`: `extract_recent_prompts()`関数の`count`パラメータ


## トラブルシューティング

### Hookが動作しない場合

1. Claude Codeを再起動したか確認
2. スクリプトに実行権限があるか確認：
   ```bash
   ls -la hooks/
   ls -la agents/
   ```
3. パスが正しいか確認：設定ファイル内のパスが実際のファイルパスと一致しているか

### エージェントシステムが動作しない場合

1. `user_hooks`セクションが正しく設定されているか確認
2. エージェントスクリプトのパスが絶対パスになっているか確認
3. Python3が正しくインストールされているか確認：`python3 --version`
4. 必要な依存関係がインストールされているか確認

### パフォーマンスの問題

- 全エージェントを常に起動すると処理が重くなる場合があります
- 必要に応じて特定のエージェントのみを有効化してください
- `~/.claude/settings.json`から不要なエージェントをコメントアウトできます

### エラーログの確認

Hookのエラーは標準エラー出力に出力されます。Claude Codeのログを確認してください。

エージェントのログは各エージェントの実行時に個別に出力されます。
